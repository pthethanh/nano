## [2026-08-20] maintenance | full-repo correctness audit and fix pass (42 findings)
- Ran a full-repo review (correctness, flexibility, generics, ease-of-use) across every package, then fixed all 42 findings one by one: for each, wrote a failing test that proved the bug, fixed it, confirmed green, then ran `go build && go vet && go test -race` on the affected module. Full-repo regression (root + all 7 submodules) is clean.
- **Critical fixes (6):** `grpc/interceptor/logging.Response()` was a dead option — response payloads (potential PII/secrets) were logged unconditionally regardless of the option. `grpc/interceptor/recovery`'s default panic handler leaked the full stack trace (and panic value) to the RPC client as the status message; now logs server-side via slog and returns a generic `codes.Internal`. `metric/memory.Reporter.Named()` nil-panicked on first use and its prefix was dead even without the panic; fixed by giving `Reporter` its own `prometheus.Registry` (also fixes a related bug where two independently-constructed `Reporter`s with the same metric name would panic on the shared global registry). `plugins/broker/watermill`'s consume goroutine busy-looped forever after unsubscribe — root cause was worse than it looked: the `select` watched the wrong context variable (`ctx` instead of the cancelable `newCtx`) *and* was missing a `return`. `broker/memory.Unsubscribe()` never called the map-cleanup closure, permanently leaking subscriber map entries. `grpc/health`'s HTTP endpoints always returned `200 OK` regardless of actual status, breaking any LB/k8s probe that reads the status code instead of the body.
- **Other correctness fixes:** data races in `broker/memory` (`br.opened`, now `atomic.Bool`) and `plugins/broker/kafka.Open()` (proved with a real sarama `MockBroker`, no live Kafka needed); `kafka.OnAsyncPublishFailure`'s `PublishError` was hardcoded to `*broker.Message` so the recovered message was always `nil` for any other `T` — made generic (`PublishError[T]`); `config.WithLogger` was a complete no-op; `status.New`/`Error` produced a garbled `"%!(EXTRA...)"` message when called with an empty format string and args; kafka/nats `Close()` panicked/errored when called without a prior successful `Open()`; `nats.Event.Ack()` errored (not silently) on plain core-NATS messages since it forwarded to a JetStream-only API — now a documented no-op, matching `broker/memory`'s convention; `grpc/interceptor/auth`'s `MapAuthenticator` let a malformed `Authorization` header (0 or 3+ words) fall through to the empty-key default authenticator; sentinel errors across `circuitbreaker`/`ratelimit`/`concurrencylimit`/`auth` carried no gRPC status code (surfaced as `codes.Unknown`) — now wrapped with the appropriate code at definition; `grpc/server.Default()`/`SetDefault()` and `log.Default()`/`SetDefault()` both had the same check-then-act race (`sync.Once` + Load-then-Store) — both replaced with `atomic.Pointer.CompareAndSwap`; `validator.Default()` had a `sync.Map` TOCTOU race on first construction per tag — reliably reproduced, fixed with `LoadOrStore`; `grpc/interceptor/tracing` and `metric/grpc` client-stream wrappers never finalized (span/metric) an abandoned stream that was never given a terminal error — fixed with a `context.AfterFunc` safety net in both.
- **One investigated finding turned out to be a false positive**: the suspected `grpc/interceptor/retry` reply-reuse-without-reset bug doesn't actually occur, because grpc-go's default codec calls plain `proto.Unmarshal`, which resets the destination message before decoding unless `Merge: true` is explicitly set (verified via `go doc` and reading `google.golang.org/grpc/encoding/proto`). Kept the test as a regression guard instead of "fixing" a non-bug.
- **Flexibility/generics/API fixes:** `broker.PublishOptions` was dead API surface (zero fields, no `Apply`); fleshed out with a real `Headers map[string]string` and wired into all three network transports (kafka record headers, watermill message metadata, nats — switched `conn.Publish` to `conn.PublishMsg` to support `nats.Header`). `grpc/server.TLS()` panicked on a bad cert/key path; added an additive `TLSErr` that returns an error instead, keeping `TLS()`'s existing (tested) panic-on-invalid-input contract unchanged. Unified the `Address` broker/cache option shape across kafka/nats/redis on variadic `...string` (kafka was `[]string`, nats was a single comma-joined `string`). Fixed `grpc/client.NewTokenCredentials`'s boolean-variadic footgun (`secure ...bool` → required `secure bool`).
- **Ease-of-use fixes:** `grpc/interceptor/logging.ClientContextLogger` did a case-sensitive metadata lookup while `ServerContextLogger` was case-insensitive; `grpc/interceptor/auth` imported `golang.org/x/net/context` instead of stdlib; `status.go` used `fmt` as a parameter name in 19 places, shadowing the `fmt` package; added missing doc comments to `plugins/broker/kafka`'s exported API to match its nats/watermill siblings; deleted a redundant duplicate `grpc` import emitted by the `cmd/protoc-gen-nano` generator (verified inert — regenerated `examples/helloworld` and the affected file was byte-for-byte identical, since the duplicate was already deduped downstream).
- Two double-`Open()` guard findings were investigated per-package: `broker/memory` had a real bug (confirmed via goroutine-count test, 50→102 goroutines on a second `Open()`) and got an `atomic.Bool` CompareAndSwap guard; `cache/memory` did not, because the underlying `ttlcache.Cache.Start()` already guards against double-start internally (confirmed by reading its source).
- Also clarified (via doc comments, not behavior changes) that `cache/memory.Get/Set/Delete` work immediately after `New()` without requiring `Open()` first (unlike `broker/memory`, which does enforce open-before-use), and that `cache/memory.Close()` deliberately ignores its own validation error to stay safely callable via `defer` regardless of whether `Open()` ever ran.

  - Updated all three consumers: `plugins/broker/kafka` (`types.go` `JSONCodec[T]`, `kafka.go`, `consumer.go`, `options.go`), `plugins/broker/nats` (`types.go` `JSONCodec[T]`, `nats.go`, `options.go`), `plugins/broker/watermill` (`types.go` `jsonCodec[T]`, `watermilk.go`).   - Breaking change to the public `broker.Codec` interface and the `Codec[T]` option constructors in all three plugin modules; no in-repo test or example called these directly, so nothing else needed updating. Root and all three plugin modules build, vet, and test clean.
- While generifying `grpc/interceptor/authz.RequestFromContext`/`NewRequestContext` (now `RequestFromContext[T any](ctx) (T, bool)`, mirroring the file's existing `FromAnyContext[T]`/`NewAnyContext[T]` pair), found and fixed a latent bug in that existing pair: `anyContextKey` was a single non-generic struct, so every type T sharing the same context chain collided on the same context key (last `NewAnyContext` call for any type shadowed all earlier ones, contradicting the function's own doc comment). ## [2026-08-20] feature | seven production-grade gRPC framework additions
Added the 7 gaps identified when asked "what's missing to production grade" for nano as a standalone gRPC toolkit (not the `lake` HTTP-only project, which was ruled out as a fit since it uses no gRPC at all). Each new behavior has a test; existing tests + full regression across root and all 8 submodules (including the new `plugins/ratelimit/redis`) stay green.
- `grpc/interceptor/validation` (new package): `UnaryServerInterceptor`/`StreamServerInterceptor(v Validator)` where `Validator` is a local `Validate(ctx, v any) error` interface — `validator.Default()` satisfies it structurally, no import needed. Rejects with `codes.InvalidArgument` before the handler runs.
- `grpc/interceptor/deadline` (new package): `UnaryServerInterceptor`/`StreamServerInterceptor(opts...)` with `WithDefault(d)` (applies d when the caller set no deadline) and `WithMax(d)` (caps any deadline, including a caller-set one, but never lengthens a shorter one). Both together pick `min(def, max)` when the caller set nothing.
- Keepalive: `grpc/server.Keepalive(params, policy)`/`KeepaliveDefaults()` (new `keepaliveOpt` custom option, appends `grpc.KeepaliveParams`/`KeepaliveEnforcementPolicy` to `serverOpts`) and `grpc/client.WithKeepalive(params)`/`WithKeepaliveDefaults()`. Defaults: server 60s/20s ping+timeout with `MinTime 30s, PermitWithoutStream: true`; client 30s/10s with `PermitWithoutStream: true`.
- `status/details.go` (new file in the existing `status` package): `WithErrorInfo`/`WithBadRequest`/`WithRetryInfo` build `*Status` values carrying `google.rpc.ErrorInfo`/`BadRequest`/`RetryInfo` details (`google.golang.org/genproto/googleapis/rpc/errdetails`, already an indirect dep, no new dependency needed); `ErrorInfo(err)`/`BadRequestViolations(err)`/`RetryDelay(err)` extract them back out. Multiple detail types can be attached to one `*Status` and all survive the `.Err()`/wire round-trip.
- mTLS: `grpc/server.MutualTLS(certFile, keyFile, clientCAFile)`/`MutualTLSErr(...)` (requires+verifies client certs signed by the given CA); `grpc/server.PeerCertificate(ctx) (*x509.Certificate, bool)` extracts the verified peer cert via `peer.FromContext`+`credentials.TLSInfo`; `grpc/client.MutualTLSCredentials(certFile, keyFile, caFile)`/`WithMutualTLS(...)` for the client side. The self-dial the internal gateway uses to call the gRPC server now also presents a client cert (reusing the server's own cert) and trusts `clientCAFile`, since the gRPC server requires client certs from every caller including its own gateway.
  - **Found and fixed a real pre-existing bug while building this**: `grpc.Creds(...)` was never added to `serverOpts` for a gRPC listener started via `SeparateAddresses`/`SeparateListeners` — that mode calls `grpcServer().Serve(lis)` directly, bypassing the HTTP server's `ServeTLS` (and thus all TLS) entirely. `TLS()`/`TLSErr()` now also build a `credentials.TransportCredentials` and add `grpc.Creds(...)`, fixing plain TLS too, not just the new mTLS path.
  - Verified end-to-end with a real generated CA + server/client cert chain (`grpc/server/mtls_test.go`): valid client cert succeeds and `PeerCertificate` returns the right CommonName; no client cert is rejected; a client cert signed by a different CA is rejected.
- `grpc/servertest` (new package): `New(t, services, opts...) *grpc.ClientConn` — bufconn-backed in-process test harness so consumers can test their own nano-based services without a real socket.
  - **Found and fixed a second pre-existing bug while building this**: `Server.useSingleAddress()` string-parsed both listener addresses via `net.SplitHostPort` to decide single- vs separate-address mode. `bufconn.Listener.Addr().String()` is the literal string `"bufconn"` (unparseable), so `Listener(bufconnLis)` (same object for both grpc and http) was misdetected as separate-address mode, which would have raced two `Accept()` loops on one listener. Fixed by preferring listener-pointer-identity (`srv.lis == srv.httpLis`) over string-parsing whenever both listeners are already set, falling back to the string heuristic only when using `Address()`-style config (no explicit listeners yet).
- `plugins/ratelimit/redis` (new module, added to `go.work`): `Limiter` implements `grpc/interceptor/ratelimit.Limiter` (`Allow(ctx) error`) via a Redis fixed-window counter (INCR+EXPIRE) — up to `Limit(n, window)` calls per key, state shared across every replica (unlike the in-process `ratelimit.NewTokenBucket`). `KeyFunc(fn)` derives the bucket key from context (default: one global bucket). Returns `ratelimit.ErrLimited` (already `codes.ResourceExhausted` from the earlier audit fix) on rejection. Mirrors `plugins/cache/redis`'s option/module conventions exactly (`Address(...string)`, `Client(...)`, `Options(...)`, `miniredis.RunT` for tests — no real Redis needed). Built with `go work sync` rather than `go mod tidy` to avoid it reaching out to the network for the local `nano` module and downloading the stale published version instead of resolving via the workspace.
